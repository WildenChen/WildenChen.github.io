# 第八章 多型與轉型

多型，又稱￼多態，英文名叫「Polymorphism」，意思是多種型態。多型的完整意思是：透過繼承，一個類別可以當成多種類別來使用。 首先，它當然可以作為自己本來的類別來使用，其次，它也可以當成自己所有父類別的類型來使用，最後，它可以當成自己所實現的協定\(Protocol\)類型來使用。

所謂形態，實際是指資料類型\(Data Type\)。狹義上，一個物件的資料類型就是它所屬的類別。廣義上，一個物件的資料類型包括自己所屬類別、自己父類別和所實現的協定類型。這基本上是上一段文字的另一種表述。

多型，這是物件導向程式設計的三大特色中的最後一個，也將 OOP 的強大表現得更加淋漓盡致。從一定的角度看，封裝和繼承幾乎是為了實現多型而準備的。

## 使用多型的好處

首先，多型將促使我們思考更加抽象，從原有的實際的類別提升到了資料種類別的角度。實際的類別代表著實際的類型，但資料種類別則代表著更廣泛的概念。

比如説，父類別和所有的子類別是不同的類別，但可以都屬於同一個資料種類別 — 父類別也可以有多個類別，不繼承自同一個父類別，但卻實現了同一個協定\(Protocol\)，我們也可以把這些類別看成一個資料種類別一一實現了同一個協定\(Protocol\)。從而，多型讓我們更多地考慮某個資料種類別能幹什麼事，而不用關心實際的類別是什麼。

對於初學者而言，剛剛接觸這些概念可能有些摸不著頭緒，很正常。本章就是為了解答這些疑問寫的。看完本章後，你再回￼過來讀這段話，就有更加深刻的體會。

其次，多型讓我們的程式碼更加易於擴充功能，更加有邏輯性和可讀性。所謂更加易於擴充功能，是指我們可以在少量甚至不修改現有程式碼的基礎上加入新的功能類別，從而使程式碼更加健壯，也更容易成長。順便提一句，大部分的設計模式都是基於多態而建立的。

## 多型在程式碼中有的實際表現

在本章的實際程式碼實例中，我們會看到，經常是一小段程式碼就可以實現多種不同的功能。這是因為許多不同的實際類別，都被看成同一種資料類型。這些實際類別的物件的同一種方法在這段程式碼執行中，表現出了不同的結果，反映了這些實際類別對這種方法的實際實現，這正是多型的表現。
