# 為什麼需要封裝

看了上面的介紹，對封裝有個模糊印象之後，再來詳細説説 為什麼需要封裝，也就是説，為什麼會產生封裝這個概念，以及封裝到底是為了解決什麼問題。

以下的解釋稍顯抽象，對於沒有專案製作經驗，沒有用過封裝概念的 OOP 新手，初看封裝時略有迷茫，這是完全正常的。 可以帶著迷惑，繼續硬著頭皮閲讀全章,，之後再回過頭來温習，相信會有更深的體會。程式碼編寫越多，對本節的理解就會越深。

### 封裝使修改程式碼更加容易和安全

封裝使修改程式碼更加容易和安全。開發行動應用程式和所有其他語言開發軟體一樣，會經常修改程式碼並且 Debug 。一般來說，軟體的修改和 Debug 時間可能會與開發時間相等，甚至更長。 因此，程式開發者所寫的程式碼要經得起不斷的修改。尤其是當編寫的程式碼要提供給第三方使用時，更要小心你所做的修改，確保你的修改不會危害其他程式碼的穩定性。

如何確保穩定性？每個類別有那麼多的屬性、方法，要如何知道其他程式師使用了哪些成員？不知道就無從修改！如果有個標識，標識哪些是第三方可以存取的，哪些是他們不能存取和修改的就好了，這就是存取控制字元的事情了。

一般用 interal 表示成員可以被套件內的所有外部成員存取， private 表示只能被目前類別成員存取，這是最基本的兩種存取許可權。 隨著命名空間與 framework 的引入，Swift還有更加豐富和靈活的存取許可權控制。

## 封裝讓程式碼分成一個個相對獨立的單元

封裝讓程式碼分成一個個相對獨立的單元，易於修改和替換。最小的單元當然是單一一個的類別。一般的單元都有數個類別，共同合作執行一個任務。程式碼單元，又稱為模組，在 Swift 中的表現往往就是一個個的 Library 。而一個行動應用程式 ，就是由若干個程式碼單元共同構成的。每個單元都有向外部開放的成員，以及不向外部開放的私有成員。

開放的成員代表著對外部的承諾，表明這個單元可以做什麼事情。不開放的成員包含著這些功能在單元內部的邏輯。我們在修改程式碼單元時，只需要關注保持對外開放的成員行為不變，對私有成員則可以自由修改。甚至，我們可以完全覆寫某個程式碼單元，只要保證它對外部的開放成員和以前相同就沒有問題。這樣就保證了程式碼單元的修補和替換更加安全，軟體維護和修改都能兼顧。

## 封裝讓整個軟體發展的複雜度大大降低

封裝讓整個軟體發展的複雜度大大降低，這點也是最重要的。 舉例而言，我們每個人並不清楚汽車的所有組成部分，也不清楚汽油如何進入發動機、如何帶動引擎使傳動器最終發動起來，但這並不影響我們開車。為什麼？因為我們知道只要轉動方向盤汽車就會按我們轉動的方向轉動、踩下刹車就會停止。只需方向盤、離合器、刹車、儀表盤等的使用方法就可以了。內部的實現原理各種汽車相互不同，和我們的使用無關。

應用程式也是如此，透過封裝，將細節的實現隱藏起來，讓軟體的複雜程度大大降低。 首先要做的是打好框架、劃分好各模組，然後才是實際的各個模組的程式碼編寫開發。設計開發軟體時，也只需要思考抽象的模組之間的協同工作方法即可，不需要細化到每個過程的實際實現，模組之間依賴的程度大大降低\(耦合性\)。這正是物件導向程式設計相對於流程式程式設計的巨大優點之一。

封裝的思想，有一個經典的術語 - 黑箱 \(BlackBox\) 。在黑箱理論中，將所有的物件都看成一個封裝好的黑箱子，物件公開一些供外部存取的屬性和方法。 程式設計師透過這些屬性和方法與物件打交道，而並不知道物件內部是如何實現的。透過忽略了這些細節，減輕了我們的腦力負擔，從而使我們能在更高的層次上考慮軟體的架構設計。越複雜的系統，越能體現這種物件導向思維方法的巨大優勢。

從根本上説，降低複雜度才是封裝這個思想產生的最真實的原因。程式碼易於修改、替換、複用等只是這一點附帶的好處而已。
