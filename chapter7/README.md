# 第七章 複合與繼承

何時使用複合，何時使用繼承，這是 OOP 程式中的一個經典的討論，直至今天依然爭論不休。除去過於學術化和理論化的分歧，納入已成熟的觀點，筆者秉承實用好記的原則給出以下建議。

首先，仍然強調謹慎使用繼承。新手中濫用繼承是非常普遍的現象。雖然繼承稱物件導向三大思想時，但這並不意味著可以隨便使用。

不正確地使用繼承，不僅是程式碼維護的災難，也是真實邏輯的扭曲。在基於 cocoa touch framework 下所開發的 App 中，雖然幾乎每個類別都會使用繼承，但是需要用到的情況也只有「因為必要」而已，多數我們開發的 App 應用程式，也只不過繼承 UIViewController 與 UIView 而已。

因為繼承沒有掌握好時，會導致父類別與子類別的耦合性過於高，如果有需要修改或維護，則牽一髮而動全身。但若善用此特性，則會因為繼承而導致修改與維護的時間大量縮短。

至於如何取捨，建議新手開發時，只要繼承「必須」繼承的類別，其次再評估複合是否能完成。隨著經驗的增長，更能掌握複合與繼承的使用時機。
